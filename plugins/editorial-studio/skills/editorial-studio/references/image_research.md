# Universal photo and image research protocol

Covers **people, organizations, travel, food, products, architecture, nature, property, culture, events, and general visual storytelling**. Never reduce the research workflow to one category.

## 1. Identify target and image need

For each page/slot define subject, identity-critical details, medium (actual photo, historical archival, diagram, illustration), orientation, approximate crop, resolution and intended circulation.

For a specific person/product/place, a photograph must show that subject rather than a generic illustration. Synthetic imagery may be used only where editorially appropriate and **explicitly labelled illustration**, never as photographic evidence.

## 2. Prioritize provenance

1. Photos supplied by user with permission to use.
2. Creator/brand/venue original website or verified press/media kit, when usage terms permit.
3. Licensed professional/editorial photography with documented scope.
4. Wikimedia Commons assets with verified license and attribution requirements.
5. Clearly labelled AI-generated illustration only when genuine photography is not required and the use is suitable.

Search-engine previews, marketing thumbnails and social reposts are discovery aids, not rights evidence or originals.

## 3. Research and inspect

Use the dashboard **Research imagery** links or a connected browser. Find the original source page, locate an actual JPEG/PNG/WebP resource, verify subject correspondence and check usage terms. Do not run bulk crawlers against third-party websites. Do not bypass sign-in, anti-bot checks or restricted downloads.

The local optional **Import from direct image URL** action downloads only a manually selected public HTTPS image file. Network accessibility does not establish a license. The file enters the project marked `approved=false` and must be reviewed in the visual preview before approval.

## 4. Provenance record for EACH photo

- Local path/filename, width, height.
- Source page URL or a meaningful file provenance description.
- Direct download URL if used (optional, kept separately).
- Photographer/organization credit.
- License or permission evidence and usage scope (`own`, `permission`, `licensed`, `private_reference`).
- Actual image matching the subject, visual quality and crop suitability.
- Editorial approval (separate from any automated download).

## 5. Rights and publication

`private_reference` is suitable only for a personal review edition and must not be used in a public/commercial version without clearance. Corporate use may also require appropriate permission; classify internal/external distribution and have a responsible editor verify rights.

Never claim "royalty free" means "no conditions", never strip mandatory credit/license terms, and never infer permission because the photo is on a restaurant, product or news website.

## 6. Failure behavior

If the exact legitimate photo cannot be sourced: present candidate sources and explain what's missing. Leave that slot unapproved; the final export remains locked. Do not fake a photographer, crop a watermarked image, or substitute a lookalike.
